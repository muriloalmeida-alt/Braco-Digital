# BRAÇO — Design Ready Governance

## 1. Novo gate de desenvolvimento

Toda história com impacto de interface exige:

> **Product Ready + Design Ready + Tech Ready**

## 2. Product Ready

- objetivo claro;
- história;
- regras de negócio;
- critérios de aceitação;
- dependências;
- prioridade;
- escopo.

## 3. Design Ready

- fluxo definido;
- arquitetura/navegação compreendida;
- componente M3 ou padrão BRAÇO identificado;
- estados relevantes definidos;
- empty/loading/error definidos quando aplicável;
- comportamento Compact definido;
- comportamento Medium/Expanded definido quando relevante;
- conteúdo/labels críticos definidos;
- acessibilidade considerada;
- interação definida;
- referência de design documentada.

## 4. Tech Ready

- arquitetura compatível;
- dependências técnicas conhecidas;
- contratos necessários identificados;
- riscos críticos tratados;
- decisão técnica suficiente para iniciar.

## 5. Responsabilidade

### GPT — PM + Product Designer
Responsável por Product Ready e Design Ready.

### Claude — Engineering
Responsável por Tech Ready.

### Murilo — PO / Sponsor
Decide estratégia, prioridade e mudanças relevantes de produto.

## 6. Handoff

Engenharia recebe:
- User Story;
- critérios;
- regras;
- referências de Design;
- estados;
- comportamento responsivo;
- dúvidas já resolvidas ou explicitamente abertas.

## 7. Mudança durante desenvolvimento

Se Engenharia precisar mudar experiência:
1. registrar;
2. retornar ao GPT;
3. decidir;
4. atualizar docs;
5. implementar.

## 8. Definition of Done de Design

Design não termina no handoff.

No review:
- comparar implementação com intenção documentada;
- validar estados;
- validar responsividade;
- validar conteúdo;
- validar acessibilidade;
- registrar ajustes.
