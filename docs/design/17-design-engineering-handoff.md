# BRAÇO — Design ↔ Engineering Handoff

## 1. Objetivo

Evitar que Engenharia precise inferir decisões de experiência durante implementação.

## 2. Entrada para Engenharia

Para cada história com UI, fornecer:

- User Story;
- regras;
- critérios de aceitação;
- fluxo;
- padrão M3;
- padrão BRAÇO quando houver;
- estados;
- responsividade;
- conteúdo relevante;
- acessibilidade.

## 3. O que Engenharia pode decidir

Engenharia decide:

- estrutura de código;
- bibliotecas;
- arquitetura;
- performance;
- cache;
- APIs;
- persistência;
- detalhes técnicos de implementação.

## 4. O que Engenharia não altera sozinha

- hierarquia da experiência;
- significado de status;
- fluxo;
- labels relevantes;
- regras de interação;
- comportamento aprovado;
- composição funcional que mude experiência.

## 5. Divergência

Ao identificar limitação:
- documentar;
- explicar impacto;
- propor alternativas;
- pedir decisão.

## 6. Review

O review de uma entrega com UI considera:

- funcionalidade;
- fidelidade à experiência;
- estados;
- adaptabilidade;
- acessibilidade.
